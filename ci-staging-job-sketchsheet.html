ci.yml — adding the staging job

Same file, three changes. Here's exactly what each one does.

push → develop → deploy-staging → staging service
push → main → deploy-prod → prod service
1

The trigger widens

  • Before → only main was watched at all
  • Now → develop is watched too, for both push and PR
  • Why → staging gets the exact same quality gate prod does — nothing skips lint/test just for being "only staging"
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]
brand new job 🆕 2

New job → deploy-staging

  • needs: lint-and-test → same gate as prod, tests must pass first
  • if: ref == develop → only fires on a push to develop, never main or a PR
  • secrets.RENDER_STAGING_DEPLOY_HOOK → the new secret, points at the staging Render service specifically
deploy-staging:
  needs: lint-and-test
  if: github.event_name == 'push' &&
      github.ref == 'refs/heads/develop'
  steps:
    - run: curl -f "${{ secrets.RENDER_STAGING_DEPLOY_HOOK }}"
3

Renamed → deploy-prod

  • Same job as before → just renamed, now that there are two deploy targets to tell apart
  • Still gated on main → behavior is completely unchanged
  • Still uses RENDER_DEPLOY_HOOK → the original secret, untouched
deploy-prod:            # was: deploy
  needs: lint-and-test
  if: github.event_name == 'push' &&
      github.ref == 'refs/heads/main'
  steps:
    - run: curl -f "${{ secrets.RENDER_DEPLOY_HOOK }}"
